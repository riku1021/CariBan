## 🎯 このドキュメントの結論

> **一言で言うと** 提示案「就活OS（AI＋管理＋面接録音）」は、就活生が**選考を跨いで学びを引き継げない**という問題への**1つの手段仮説**にすぎない。現時点で最も妥当な Problem 仮説は、**「就活で生まれる『企業×自分』の意思決定と面接学びが、次の選考に渡らず、毎回ゼロから準備が始まる」** ことである。

## 💡 Executive 洞察（最大3）

1. **管理の煩雑さと経験の非蓄積は別症状に見えて、根は同じ** — 「企業×自分」の関係（志望理由・エピソード・面接で話したこと）が一箇所に残らず、次の行動に変換されない。[INFERENCE]（旧04・00-business-discovery より）

2. **「就活管理アプリ」は入口として強いが、本質 Job ではない** — Notion / Calendar / Spreadsheet で「企業リスト管理」はある程度代替可能。差別化の芯は**個人固有の就活履歴の資産化**（OpenWork 等は企業情報を資産化する方向）。[INFERENCE]

3. **日程調整は切実な Pain だが、手段固定の中心にすべきでない** — エージェント並行時の「提示済み候補」管理は強い摩擦だが、単体では汎用カレンダー／人力の延長に留まりうる。Reframe の中心は**学びの連鎖**に置く方が手段非依存。[HYPOTHESIS]

## 🪜 なぜ梯子

**採用する幹**: 面接後の忘却 → 非蓄積 → リセット、の連鎖

| 段 | なぜ？ | 到達点 |
| -- | ------ | ------ |
| 1 | なぜ面接準備に毎回時間がかかる？ | 前回の質問・自分の回答・改善点を探し直している |
| 2 | なぜ探し直す？ | 面接後の振り返りが続かず、断片的なメモか記憶だけ |
| 3 | なぜ振り返りが続かない？ | 面接情報が「企業×自分」の文脈で残っておらず、整理のコストが高い |
| 4 | なぜ文脈で残らない？ | 情報がカレンダー・ナビ・エージェント・メモに分散し、**意思決定の連鎖**（なぜこの志望か→何を話したか→次に何を直すか）が途切れる |
| 5 | なぜ連鎖が途切れる？ | 就活ツールは「記録」や「企業ファクト」はできても、**個人固有の選考学びを次の選考入力に変換する**設計になっていない |

**Root Cause 仮説（断定しない）**:

> 本当に解決したいのは **「情報が散らばっている」ことそのもの** ではなく、**「就活で更新される『企業×自分』の知識が、選考を跨いで再利用可能な形で残らない」** ことである。

## 📊 Before / After

| 観点 | Before | After |
| ---- | ------ | ----- |
| 状態 | 面接ごとに記憶と断片メモに依存。「あの会社で何を話した？」が答えられない | 企業×自分の文脈と面接学びが蓄積され、次回準備の起点が常にある |
| 行動 | 毎回 ES・想定質問・志望動機をゼロから組み立てる | 過去の回答・改善点・使用済みエピソードを起点に差分だけ準備 |
| 感情／コスト感 | 準備の繰り返しによる疲労・不安。「また同じ失敗」を恐れる | 積み上がりによる自信。準備時間の短縮 |

**人を移す一文**:

> 就活生を **「毎回忘れてゼロから準備する状態」** から **「選考が進むほど自分のストーリーが強くなる状態」** へ移す。

**100%成功で不要になる行動・仲介・摩擦・不確実性**:

- 面接前の「前回何を話したか」探し直し
- 企業間で同じエピソードを矛盾なく使えるかの不安による過剰準備
- 断片的メモの転記・重複入力（学びが一箇所に残れば）

**市場構造への含意（仮説メモ）**: 企業情報プラットフォーム（OpenWork 等）とは逆方向に、**個人データ**のロックインが起きうる。02で非顧客・BM候補と接続。[HYPOTHESIS]
