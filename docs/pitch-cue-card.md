> **状態: DRAFT** — 2026-08-26。発表の口頭順・ページつなぎ用。**正は各章 LOCKED／DRAFT**。ここだけで数字・Must・Problem を発明しない。

### 全体の物語（つながり一筆）

```text
開き(0) → 問いかけ(0.5) → 問題(1) → 課題(1.5) → 誰(2) → 代替の限界(3) → Out(4)
  → Must(5) → 検証(6) → 支払者(7) → 届け方(8) → 数字(9)
  → Trust(10) → Ask(11) → 質疑
```

口頭の骨: 「問いかけ → **問題**（引き継がれない・毎回ゼロ）→ **課題**（渡せる状態のギャップを埋める）→ すでに工夫している学生 → 無料スタックでは引き渡しが解けない → 管理完結はやらない → F4+F1–F3を検証 → 学校が年額で払う仮説 → 紹介でCCへ → 単価とBEPは仮説・CAC未 → 非共有 → 今はBuildと11」

> **用語**: **問題**＝起きている摩擦・症状。**課題**＝埋める状態ギャップ（手段なし）。混ぜない（06①）。

## P0 開き ★

- **口頭**: 「並行就活で、面接の学びを次の準備に渡せる状態をつくる話です。」
- **キー**: コンセプト＝学びと「企業×自分」を次へ渡す（07）。「就活OS／AIプラットフォーム」を顔にしない。
- **言わない**: 完成品・PMF・合格保証。
- **→次**: 「一つだけ、聞いていいですか。」→ **P0.5**

---

## P0.5 問いかけ（フック）★

聴衆を自分の経験に寄せてから **問題** に入る。手を挙げさせても、間を取って頷きを見てもよい。

- **口頭（主）**: 「みなさん、選考を並行しているとき、**前回の面接で何を話したか**を、次の企業の準備にちゃんと使えていますか？」
- **口頭（代替・場が就活経験者向け）**: 「みなさん、面接のあと、次の準備を**またゼロから**やり直したこと、ありませんか？」
- **口頭（代替・CC／教員向け）**: 「支援の場で、学生が**毎回ゼロ準備**になっている姿を見たことはありますか？」
- **キー**: 答えを急がない（2〜3秒の間）。挙手・頷きを受けてから「まず、そこで起きている**問題**から」とつなぐ。問いの意味は06に接続するが、**ここで課題の定式化も解決策も言わない**。
- **言わない**: 「全員が困っている」と決めつける。問いの直後に機能一覧へ飛ぶ。統計の断定（11前）。
- **→次**: 「起きていることを、はっきり言います。」→ **P1**

---

## P1 問題 ★

**問題**＝起きている摩擦・症状（まだ「何を埋めるか」は言わない）。

- **口頭**: 「探し直し・転記・見落としの手間に加え、前回の面接やESで得た学びが、次の選考に引き継がれていない。並行応募だと、毎回ゼロから準備が始まる。」
- **キー**: 06① **問題**。症状の列挙。問いかけの反応を一句で受けてから定式化してよい。**仮説**（一般化は11）。
- **言わない**: 「だからアプリを作る」。課題の骨格や Must をここで先出しする。「みんなが困っている」の断定。管理ツール不足＝本課題、と言い切ること。
- **→次**: 「では、私たちが解く**課題**は何か。」→ **P1.5**

---

## P1.5 課題 ★

**課題**＝埋める状態ギャップ。手段（録音・一元管理アプリ等）は入れない。

- **口頭**: 「課題は、選考で得た学びと『企業×自分』の文脈が、次の準備に**渡せる状態になっていない**ギャップを解消することです。」
- **キー**: 06① **課題（骨格）**。必要なら本質課題1文（06③）を短く添えるが、顔は骨格ギャップ。中心は学びの連鎖。管理 alone は本質の代替にしない。
- **言わない**: 「一元管理を構築する」「録音する」等の手段表現を課題として言う。問題と課題を同じ一文に畳む。
- **→次**: 「では誰の話か。」→ **P2**

---

## P2 誰向け ★

- **口頭**: 「最初は、もう自力で管理している層。10社以上・3社並行・面接5回以上の大学生・院生・専門学生。」
- **キー**: 10 Beachhead。**仮説ロック**。すでに Notion／Sheet／Calendar で工夫している人。エージェント必須にしない。
- **言わない**: TAMの人数を顧客数のように話す。SOMの断定。
- **→次**: 「その人たちは今、何で足りているつもりか。」→ **P3**

## P3 なぜ今の道具では足りない ★

- **口頭**: 「無料トラッカーと Notion とナビの組み合わせは、管理と締切には強い。解けないのは、学びと企業×自分を次の準備に渡すこと。」
- **キー**: 09 勝つ一文・最強代替。差は管理機能の有無ではない。個人履歴の引き渡し。
- **言わない**: 「競合がいない」。OpenWorkを同土俵の機能競争相手にする。
- **→次**: 「だから、こちらがやらない戦いを先に言う。」→ **P4**

## P4 やらないこと ★

- **口頭**: 「口コミ網羅、マッチング、紹介料、音声の第三者共有、管理Todoだけで完結するアプリ、はやらない。」
- **キー**: 06 Out／09 やらない戦い。入口の管理は条件付き。コアは引き渡し。
- **言わない**: 後でマッチングもやる、と本編で広げる。
- **→次**: 「では検証で何を載せるか。」→ **P5**

## P5 Solution / Must ★

- **口頭**: 「Mustは四つ。選考一覧の入口（F4）と、残す・辿る・渡す（F1–F3）。Webアプリで検証する。」
- **キー**: 13 Must＝F4+F1–F3。実験形＝Web+PG。録音AI・候補日本格・ダッシュボード肥大は Won't。**出荷できた ≠ SUCCESS**。
- **言わない**: 完成形カタログ（付録）を本編の約束にする。Concierge／Notion補助を自社提供の中心にする（方針上アプリ本線）。
- **→次**: 「どうやってそれが効くか壊しにいくか。」→ **P6**

## P6 検証の物語 ★

- **口頭**: 「実装を進めつつ、インタビューで言葉を取る。アプリでは、学びを次準備で使うか、管理だけで終わらないかを見る。」
- **キー**: 19: P-Build ∥ 11 → V1–V3。V1＝引き渡し。V3＝K1（管理満足で離脱）。11スキップ禁止。
- **言わない**: 実装完了＝検証完了。KILL IFの捏造。
- **→次**: 「価値が見えたとして、誰が払うか。」→ **P7**

## P7 誰が払うか ★

- **口頭**: 「学生は基本無料。大学・専門学校が年額パイロットで払う仮説。レンジ年30〜80万、中央50万。」
- **キー**: 14 B2B2C。強い証拠＝会議／発注。「興味あります」alone は弱。学生のV1観察後にWTPを格上げしやすい。
- **言わない**: 学生サブスクを主Offerに戻す。マッチング課金。登録数＝WTP。
- **→次**: 「そのOfferをどう届けるか。」→ **P8**

- **言わない**: 広告CACの架空。クリック＝成功。

## P9 数字 ★

- **口頭**: 「主軸は学校年額。基準50万。限界利益は厚めの仮説。固定費が小さければ会計上の分岐は1校未満。ただし獲得コストはまだ測れていない。」
- **キー**（16 DRAFT・再LOCK待ち）:
  - P＝年¥50万／校（¥30–80万）
  - CM基準≈¥34.5万／校・年（粗利率仮説）
  - Fixed OpEx年≈¥6万 → BEP≈**0.17校**（仮説）
  - Ceiling基準≈年5校×50万＝¥250万（≠TAM）
  - CAC / Payback＝**UNKNOWN**
- **言わない**: TAM×％で売上。楽観 alone で「いける」。CACの捏造。累積CFの絶対ランウェイ断定（手元資金未申告）。
- **任意スライド**: BEP図・累積CFは `python/output/`（質問が来たら）。本編では口頭1行で足りることが多い。
- **→次**: 「個人情報と信頼の約束。」→ **P10**

- **言わない**: 「完全に安全／適法」。録音を今の顔にする。

- **キー**: 18 WARNING＝時間競合。19＝Build∥11。Ask例（場に合わせて1つ選ぶ）:

- **言わない**: 採用計画で穴を埋める話を本編の主役にする。完成ロードマップの約束。
